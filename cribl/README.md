# Cribl pipeline for btc_parser (prod)

Prod path: Universal Forwarder → Cribl Stream → Splunk Enterprise.

Splunk treats data coming from Cribl as already parsed, so it applies **no**
index-time `props.conf`/`transforms.conf` to it. `TA-btc-parser-parsing` does
nothing there. Its job (drop header rows, set `_time`, decide which columns
become indexed fields) is done by `btc_parser_pipeline.json` instead.

`btc_parser_pipeline.json` is generated by `splunk/build_field_config.py` from
`btc_parser_app/export_schema.py`, like the Splunk confs. Don't edit it in
Cribl. Re-generate it and re-import it.

**Not yet tested against a Cribl instance.** Import it into a dev worker group
first and check it with a sample before it goes live (checklist below).

## What it does

1. Drops the CSV header row of every part file.
2. Parses each row with an explicit column list (positions from
   `export_schema.py`):
   - `btc:transactions` / `btc:inputs` / `btc:outputs`: keeps **only** the
     indexed columns plus the time column.
   - the four small sourcetypes: keeps every column.
3. Sets `_time` from `block_time` / `time` / `observed_at` / `date_unix`, then
   drops `block_time` again (not an indexed field).
4. Deletes empty values (CSV nulls), so they don't arrive as empty indexed
   fields.

`_raw` stays the original CSV row. Every top-level field left on the event is
sent to Splunk as an indexed field. The remaining columns are extracted at
search time by `TA-btc-parser-search`, the same app as on the test instance.

## Setup

- **UF**: only `TA-btc-parser-inputs` (and `TA-btc-parser-ingest-tuning` for
  `maxKBps = 0`). **Not** `TA-btc-parser-parsing`: with `INDEXED_EXTRACTIONS`
  the UF would parse the small sourcetypes itself and send every column as an
  indexed field.
- **Cribl source** (Splunk TCP, from the UF): the UF sends the files unbroken.
  Give the source an Event Breaker ruleset with one rule for
  `sourcetype.startsWith('btc:')`, type *Regex*, breaker `[\r\n]+`, timestamp
  *none* (the pipeline sets `_time`). The default max event size is plenty
  (rows are < 2 KB).
- **Route**: filter `sourcetype.startsWith('btc:')` → pipeline `btc_parser` →
  Splunk destination.
- **Splunk destination**: switch off the Cribl *system fields*
  (`cribl_pipe`, `cribl_route`, `cribl_host`, …). Otherwise each one becomes
  an extra indexed field on billions of events. Nested field serialization:
  none.
- **Splunk search head**: `TA-btc-parser-search`, `btc-parser-dashboards`.
- **Splunk indexer**: `TA-btc-parser-indexes`, `TA-btc-parser-ingest-tuning`.
- `btc:prices` may already have its own Cribl route (live prices). Make sure
  only one route handles it.

## Checklist before go-live

On a sample (`head -n 1000` of each CSV, sent through the UF into a test
index):

```
| tstats count where index=<test> by sourcetype
| tstats count where index=<test> sourcetype=btc:outputs by script_type is_coinbase block_height
| walklex index=<test> type=field | stats count by field
index=<test> sourcetype=btc:transactions | head 1 | table _time block_time txid fee_rate_sat_vb vin_count
```

- `walklex` must list only the indexed fields from `export_schema.py`, plus
  Splunk's own `host`/`source`/`sourcetype`. No `cribl_*`, no `txid`, no
  `fee_sats`.
- `_time` must equal `block_time`.
- Header rows must not show up as events.
